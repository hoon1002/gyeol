# 디자인 v4: 3D 은하

작성: 아트 디렉터 · 2026-10-17 · 바탕: `team/v4-brief.md`, `design-v3*.md`(색·글·사건 어휘는 이어 쓴다)
**순서 안내:** 모션 개발자가 시제품에 바로 쓸 수 있게 **3장(멀미 기준)과 4장(3D 공간 지도)을 앞에 두었다.** 1·2·5·6장은 그 뒤에 있다.

> **한 줄:** 우리는 은하를 '위에서 비스듬히' 본다. 은하는 천천히 돌고, 앱의 공간은 그 은하 속 장소다. 공부한 별들은 학기 동안 은하에 **나의 나선 가지**를 하나 새로 자라게 한다.

**좌표 약속:**
- 은하 원반은 XZ 평면, Y가 위다. 단위는 u(1u ≈ 1kpc 느낌)이고 원반 반지름은 15u다.
- 카메라는 `target`(바라보는 점)과 방위 az(+X에서 Y축 둘레로 반시계, °), 고도 el(원반 위 각도, °), 거리 d(u)로 적는다.
- FOV는 세로 40°로 고정한다. 확대는 FOV가 아니라 거리로 한다.

## 3. 새 멀미 기준 (회전 허용판)

**근거:**
- 넓은 시야가 시선 축을 중심으로 도는 **롤(roll)**은 자기 운동 착각(벡션)과 멀미를 가장 강하게 일으킨다. 그래서 롤은 어떤 경우에도 0이다.
- 방위·고도 회전은 느리면 안전하다. 그래서 '화면 위 별의 속도'와 '시야 각속도' 두 가지로 묶는다.
- 사용자가 일으키지 않은 움직임은 끌 수 있어야 한다(WCAG 2.2.2). 상호작용으로 생기는 움직임도 끌 수 있어야 한다(2.3.3).
- 기존 기준(design-v3 §5)은 그대로 이어진다: 번쩍임 금지, 동심원·맥동 금지, 크롬은 고정.

| 항목 | 풍부 (기본) | 절제 | 정지 (= OS 동작 줄이기) |
|---|---|---|---|
| 은하 자전 · 코어 (r ≤ 3u) 각속도 | **1.2°/s** (한 바퀴 5분) | 0.4°/s | 0 |
| 은하 자전 · 바깥 (r = 15u) | 0.24°/s (평탄 회전 곡선: Ω ∝ 1/r) | 0.08°/s | 0 |
| 자전 때문에 화면 위 별이 움직이는 최대 속도 | **≤ 8px/s** | ≤ 3px/s | 0 |
| 카메라 호흡 (입력 없을 때) | 방위 ±3°(주기 60초) · 고도 ±1.5°(90초) · 거리 ±2%(45초). 시야 각속도 ≤ 0.35°/s | 방위 ±1° · 고도 0 · 거리 0, ≤ 0.1°/s | 0 |
| 입력 없을 때 카메라가 움직이는 범위 | 장소 기준점에서 위 호흡 범위를 넘지 않는다(표류 없음) | 같음 | 0 |
| 비행 (공간 이동) | 1200–1800ms, `cubic-bezier(.65,0,.35,1)`. **방위 변화 ≤ 30°, 고도 변화 ≤ 20°, 시야 각속도 최고 ≤ 30°/s**. 거리는 로그 보간. 롤 0, FOV 고정 | 회전 0, 거리만 30% + 크로스페이드 450ms | 크로스페이드 450ms (OS 동작 줄이기면 즉시) |
| 직접 돌려 보기 (오늘에서 드래그·두 손가락) | 방위 ±35°, 고도 ±12° 범위. 최대 90°/s, 손을 떼면 관성 ≤ 0.6초 후 그 자리에 멈춤(되돌아가지 않음) | 관성 0 | 끔 (드래그하면 하늘 대신 화면이 스크롤된다) |
| 별의 생애 · 성운 흐름 (2장) | 켬 | 별의 생애만, 횟수 절반 | 0 |
| 수평선 | 원반의 기울기(화면에서 원반 장축 57°)를 고정. **롤 0** | 같음 | 같음 |
| 글 읽기 · 필기 중 (useFieldPause) | 자전 ×0.3, 호흡 0, 300ms 안에 줄임 | 자전 0 | 0 |

- **번쩍임:** 화면 전체 밝기 변화는 비행 중에도 초당 10% 이하로 묶는다.
- **연출 중첩:** 별 탄생 같은 사건은 1개씩만 한다. 자전·호흡 위에 비행이 겹치면 비행하는 동안 호흡은 0으로 섞어 내린다(300ms).
- **설정:**
  - '움직임: 풍부 · 절제 · 정지'는 그대로 쓰고, '공간 이동: 비행 · 짧게 · 끔'도 그대로 쓴다.
  - 새 행 **'은하 자전: 켬 · 느리게 · 끔'**을 추가한다. 기본은 켬이고, 끔이면 0이다.
  - OS `prefers-reduced-motion`이면 모두 정지이고 선택지는 비활성이다.

- 모든 장소의 방위는 오늘(210°) 기준 ±18° 안이다. 그래서 어느 두 장소 사이를 날아도 방위 변화가 30° 이하다(노트 228 ↔ 그래프 198 = 30°).

### 4-3. 비행 경로와 별 누르기 (3D)

- **경로:** 은하 중심 기준 구면 좌표(az, el, log d)를 보간하고, target은 직선으로 옮긴다. 방위는 짧은 쪽으로 돈다.
- **결과:** 오늘에서 안쪽 장소로 갈 때는 은하 둘레를 살짝 돌며 내려앉는 호가 된다(예: 오늘 → 집중은 방위 +10°, 고도 −16°, 거리 38 → 3.5).
- **속도:** 시야 각속도가 30°/s를 넘을 것 같으면 지속시간을 1800ms까지 늘린다. 그래도 넘으면 회전량을 줄인다(도착 방위를 기준점에서 비켜 앉힌다).
- **글자:** 나감 0–180ms, 들어옴 D − 320ms(design-v3-camera §2 그대로).
- **재입력:** 지금 위치·속도에서 이어서 난다.

| 별 누르기 | 다가감 | 보이는 것 |
|---|---|---|
| 오늘의 별 · 나의 별 | target = 그 별. d = 1.6u. 방위 변화 ≤ 15°로 별 좌석에 앉힌다 | 한 줄 정보 (design-v3-camera §3과 같은 문구) |
| 복습 별 | d = 1.2u | 카드 앞면 한 줄 / 과목 · 다음 / 이 카드 복습 |
| 노트 별 | d = 1.4u. 별 둘레 선이 60%로 | 노트 제목 / 과목 · 링크 n / 열기 |
| 시험 별 | d = 2.0u | 시험 이름 / 날짜 · D-n / 범위 복습 |

닫으면 `back()`으로 물러난다. 누름 판정은 화면에 투영한 별 위치 반경 18px(손가락 24px)로 하고, 가장 가까운(깊이가 앞인) 별을 고른다.

### 1-2. 별 · 성운 수치

- **점 수:** A 등급 40만(원반 32만 · 팽대부 6만 · 헤일로 2만), B 16만, C는 정지 이미지 1장.
  - 화면 크기는 0.6–2.6px이다. 거리가 가까워져도 별은 커지지 않고, 밝아지고 많아진다(점 크기는 +15%가 상한).
  - 밝기는 멱함수로, 등급이 하나 내려갈 때마다 약 10배씩 많아진다. 색은 흑체 온도로 정하고 채도는 −20%다.
- **볼류메트릭:**
  - 먼지·성운은 ¼ 해상도 레이마칭(24스텝)으로 그린다. 3D 노이즈 슬랩을 팔 밀도로 곱한다.
  - B 등급은 빌보드 스프라이트(먼지 600 · HII 180)로 대체한다.
  - 코어 둘레 블룸은 한 번 걸고, 회절 스파이크는 가장 밝은 별 몇 개에만 은은하게 준다.
- **팔레트 조화:**
  - 하늘의 금(코어)과 UI의 별빛 금 `#F3D29A`는 같은 계열이다. 하늘의 분홍 HII는 인주(시험 별) 계열, 하늘의 푸른 팔은 차가운 외곽이다.
  - UI의 글자색·유리는 v3 토큰을 그대로 쓴다.

## 2. 기본 생동감 (가만히 있어도 살아 있게)

| 요소 | 무엇이 | 수치 | 절제 / 정지 |
|---|---|---|---|
| 은하 자전 | 별 입자가 차등 회전한다. Ω(r) = 1.2°/s × min(1, 3u ÷ r) | 코어 한 바퀴 5분, 바깥 25분. **팔 무늬는 패턴 속도 0.5°/s로 강체 회전한다**(밀도파: 별은 팔을 지나가고 팔은 감기지 않는다. 별 밝기를 팔과의 거리로 매 프레임 조절) | 0.4°/s / 0 |

| 별의 생애 | 8–15초마다 팔 위 젊은 별 하나가 켜지고(1.5초) 다른 하나는 꺼진다(4초) | 동시에 1개. 밝기는 1등급 이하 | 횟수 절반 / 0 |
| 성운 흐름 | HII · 먼지 노이즈 좌표가 0.02u/s로 흐르고, 성운마다 밝기가 ±5%로 20–40초에 걸쳐 따로 바뀐다(서로 맞지 않아 맥동이 아니다) | ±5% 이하, 주기 20초 이상 | 0 / 0 |
| 가까운 성간 입자 | 카메라 앞 입자 150개가 아주 느리게 떠간다(v3 별가루의 3D판) | 화면 ≤ 6px/s, 크기 ≤ 1.3px | 50개 / 0 |
| 나의 가지가 자람 | 하루가 끝나면 오늘의 별자리가 나의 가지 끝으로 옮겨 간다 | 사용자가 보지 않을 때 적용(보이는 이동 0). 다음 진입 때 가지 끝 별 하나가 V11로 반짝 | 같음 / 반짝 없음 |

## 5. UI와 3D의 조화

| 원칙 | 규칙 |
|---|---|
| 2D UI는 평평하게 | DOM UI는 3D로 기울이거나 패럴랙스를 주지 않는다. 글자는 늘 선명한 2D다. 크롬(상단 3점 · 독 · 레일)은 화면에 고정된 눈의 기준점이다 |
| 글자 안전 구역 | design-v3 §2-1의 화면 좌표 그대로 쓴다. 렌더러가 마지막 합성 단계에서 그 구역의 휘도를 `#161C2C` 이하로 누르고, 0~1등급 별·HII를 70% 낮춘다. 가장자리 120px 페더. 은하 중심은 좌석(0.64, 0.42) 쪽에 두므로 코어가 글자 뒤로 오지 않는다 |
| 깊이 위의 라벨 | 3D 별에 붙는 정보는 화면에 투영한 위치를 쓰되, **누를 때만** 왼쪽 글자 구역에 한 줄로 띄운다. 별 옆에 떠다니는 HUD 라벨·지시선은 없다(회전하면 라벨이 따라다녀 어지럽다) |
| 유리 | glass + blur 20 그대로. 은하가 돌면 유리 뒤가 천천히 바뀌어 크롬이 살아 보인다(블러가 회전 디테일을 흐려 주의를 뺏지 않는다) |
| 금빛 | 주 버튼 = 코어의 빛. 화면당 1개, 면적 2% 이하 원칙 유지 |
| 성능과 아름다움 | 글이 많은 화면(노트 편집·플래너 격자)은 자전 ×0.3, 볼류메트릭 ¼ → ⅛ 해상도. 120Hz 기기에서 하늘 렌더는 60fps 상한(자전이 느려서 차이가 없다), UI만 120Hz |

## 7. 360° 개정 (M0, 2026-10-17 · 3장의 해당 값보다 이 절이 우선)

사용자 요청은 360°로 돌고, 회전할 때 눈앞을 스쳐 가는 별이 많고, 배터리·발열이 적은 것이다. **원칙은 '돌되, 롤은 움직이지 않는다'이다.**

### 7-1. 회전 · 공전 · 드래그

| 항목 | 풍부 | 절제 ('느리게') | 끔 · OS 동작 줄이기 |
|---|---|---|---|
| 자동 공전 (입력 없을 때 카메라가 은하 둘레를 돎) | **한 바퀴 6분 = 1.0°/s.** 마지막 입력 3초 뒤부터 4초에 걸쳐 0 → 1.0°/s(`inout`). 입력이 오면 300ms 안에 0 | 한 바퀴 15분 = 0.4°/s | 0 |
| 은하 자전 (3장) | 코어 1.2°/s → 바깥 0.24°/s. 공전과 **같은 방향** | 0.4 → 0.08°/s | 0 |
| 자동 움직임의 시야 각속도 합 | **≤ 1.5°/s**, 배경 별의 화면 속도 ≤ 10px/s | ≤ 0.6°/s, ≤ 4px/s | 0 |
| 드래그 · 두 손가락 | **방위 360° 무제한.** 고도는 8°–55°로 묶어 원반 아래로 넘어가지 않게 한다. 손가락을 그대로 따르고 최대 180°/s | 같음 | 드래그는 그대로 허용(직접 조작). 관성은 0 |
| 관성 | 손을 뗄 때 속도에서 지수 감쇠 τ = 0.5초, 최대 1.2초, 시작 속도 ≤ 90°/s. 멈춘 자리에 머문다(되돌아가지 않음). 3초 뒤 그 방위에서 공전을 다시 시작 | τ = 0.25초 | 0 |
| 핀치 | 거리만 장소 거리의 0.6–1.6배. FOV는 고정 | 같음 | 같음 |
| 수평선 · 롤 | 원반 장축을 화면 57° 대각선에 맞추는 **고정 기울기**(카메라 up 벡터 고정, 화면 −33°). **롤 운동은 어떤 경우에도 0**. 공전·드래그로 방위가 바뀌어도 수평선은 같은 기울기로 그대로 있다 | 같음 | 같음 |

- **비행과 360°:** 장소 지도(4장)의 방위는 절대값이 아니라 **'지금 방위 + 장소 오프셋'**으로 다시 정한다. 오프셋은 오늘 0, 노트 +18, 복습 −8, 그래프 −12, 집중 +10, 플래너 0이다.
  - 그래서 사용자가 은하를 어디까지 돌려 놓았든, 비행 한 번의 방위 변화는 오프셋 차이(30° 이하)뿐이다.
  - 비행 상한은 3장과 같다: 30° 이하, 최고 30°/s 이하, 1.2–1.8초.
  - target(데이터 별·성운)은 은하 좌표에 붙어 자전을 따라 움직이므로, 카메라는 비행이 끝날 때의 target 위치를 쫓는다.
- **장소별 공전:** 공전은 오늘·플래너·설정에서만 한다. 집중 실행 중에는 0.3°/s로, 노트 편집·복습 카드·그래프 별 열림에서는 0으로 낮춘다. 공전이 바뀌는 데는 늘 2초 `inout`이 걸린다.

### 7-3. 설정

**'은하 회전: 켬 · 느리게 · 끔'** 한 줄이 자동 공전과 은하 자전을 함께 정한다(3장의 '은하 자전' 행을 이것으로 바꾼다).
- 켬과 느리게의 값은 7-1 표와 같다.
- 끔이면 공전·자전이 0이지만, 드래그·비행·전경 별은 '움직임' 수준을 따른다.
- OS 동작 줄이기면 모두 0이고 선택지는 비활성이다.

### 7-4. 전력 상태: 우아하게 줄어들기 ('느려질 뿐 어두워지지 않는다')

| 상태 | 들어가는 조건 | 보이는 모습 | 목표 |
|---|---|---|---|
| 활동 | 입력 · 비행 · 드래그 · 사건 | 모든 것 | 하늘 60fps(UI는 기기 주사율), DPR × 1.0, 볼류메트릭 ¼ |
| 평소 | 입력 없음 0–60초 | 공전 · 자전 · 전경 별 · 별의 생애 | **30fps**(가장 빨라도 프레임당 0.05°라 부드럽다), DPR × 0.75 |
| 깊은 대기 | 입력 없음 60초 넘음 | 5초에 걸쳐 공전이 0.3°/s로 느려지고, 전경 별 30%, 반짝임 0, 성운 흐름 0 | 15fps, DPR × 0.6, 볼류메트릭 ⅛ |
| 쉼 | 입력 없음 5분 넘음 · 저전력(배터리 절약, 배터리 20% 이하이고 충전 중 아님, `saveData`) · 프레임 p95가 예산의 1.5배 넘게 10초 지속(발열 추정) | 지금 장면을 2초 크로스페이드로 **정지 장면**(3등급 +20%, 코어 대비 +6%)으로 바꾼다. 밝기는 그대로 | 0fps(바뀔 때만 그림) |
| 숨김 | 탭 숨김 · 화면 밖 | — | 0, 깨우기 0 |
| 돌아옴 | 쉼 · 숨김에서 입력 | 정지 장면 위에서 600ms 동안 속도가 0에서 그 상태의 값으로 차오른다(점프 없음) | 활동으로 |

- 상태가 바뀔 때 **밝기·구도는 바꾸지 않는다.** 속도·반짝임·전경 별 수만 줄인다. 그래서 사용자는 '은하가 숨을 고른다'로 느낀다.
- 동작 줄이기는 늘 정지 장면이다.
- 측정 지표는 성능 엔지니어와 맞춘다: 상태별 실제 그린 fps, GPU ms(타이머 쿼리), JS ms, 초당 깨우기.
