# 은하수 v3 앱 통합 브리프 (리더 작성, 2026-10-17)

## 사용자 결정·피드백 원문

> 은하수가 더 좋은거 같은데
> 은하수 디자인은 멀미가 안날거 같거든 모션들 넣었으면 좋겠어
> 그리고 이 앱의 기능들이랑 디자인과 모션이 좀 아름답게 조화를 이뤘으면 좋겠어 지금 기능이랑 디자인이 전혀 연결되고 있지 않잖아
>
> 그리고 최적화를 신경써야겠다 html로 크롬 브라우저에서 확인할 때 다른 기능으로 넘어갈 때 어두워지고 밝아지고 하잖아 그게 팟 팟 하고 바뀌는 딜레이가 좀 있는거 같아

## 결정

1. **은하수 v3로 앱 전체 전환.** 결 등고선 필드, 동심원 고리, 와이프, 물결 왜곡, 원형 타이머는 앱에서 모두 제거한다. 글 다이어트(design-v3 4-2)와 별빛 금 강조색을 적용한다.
2. **모션은 더 풍부하게, 단 멀미 안전 기준(design-v3 5장)은 그대로.** 화면 전체의 회전·확대·패럴랙스·왜곡은 계속 금지. 대신 '의미 있는 빛의 움직임'을 늘린다(별이 태어나는 빛, 별자리 선이 그어지는 것, 복습한 별이 다시 켜지는 것, 유성 같은 완료 신호 등).
3. **기능 = 하늘의 사건.** 모든 핵심 기능(집중·복습·노트·링크·플래너·시험·⌘K·이동)이 하늘에서 고유한 사건을 일으키고, 그 사건이 곧 피드백이 된다. 무엇이 무엇을 일으키는지는 아트 디렉터의 `team/design-v3-motion.md`(연결 지도)가 정한다.
4. **최적화(리더 진단):** 지금 시제품은 화면을 바꿀 때마다 정적 하늘을 다시 굽는다(`sky.ts` setScene → bake, 28–31ms 메인 스레드). 그래서 한두 프레임이 멈춘 뒤 노출 보간이 시작돼 "팟, 팟" 끊겨 보인다. 앱 통합에서는:
   - 정적 하늘은 **앱 시작 때 한 번만** 선형 HDR(RGBA16F 등)로 굽고, 노출·톤매핑·장면별 색조는 **매 프레임 합성 셰이더 유니폼**으로 처리한다 → 화면 전환에 굽기 0회.
   - 장면마다 구도가 꼭 달라야 하는 부분이 있으면 시작 직후 `requestIdleCallback`으로 미리 굽거나(타일 단위로 쪼개서 긴 프레임 없이), 아예 합성 단계 유니폼으로 바꾼다.
   - 셰이더는 시작 때 미리 컴파일·워밍업(첫 사용 시 끊김 방지).
   - UI 내용 전환과 하늘 노출 전환은 **같은 타임라인**(예: 450ms 전후, 같은 이징, 같은 프레임에 시작)으로 맞춘다. 검은 화면·흰 번쩍임 0.
   - View Transitions가 WebGL 캔버스를 스냅샷하며 깜빡이면 캔버스는 전환에서 빼고(`view-transition-name: none` 또는 전환 범위를 앱 루트로 한정) 하늘은 자체 크로스페이드로 처리.

6. 별빛 금 토큰·글꼴 굵기·셸(독/레일) v3 적용, Figma와 같은 인상.

**API 계약 규칙:** `src/fx/index.ts`의 기존 이름(FieldProvider, FieldMood, useFieldData, useSeal, useRipple, RippleSurface, useFieldTransition, useFieldPause, useMotionPrefs, RevealText, CountUp, Stamp 등)은 **그대로 두고 의미만 은하수로 바꾼다**(예: FieldMood preset → 하늘 장면, useFieldData → 데이터 별, useSeal → 별 탄생, useRipple → 그 자리 별빛 밝아짐, useFieldTransition → 동기화된 크로스페이드). 그래야 지금 앱 연결이 그대로 살아난다. 연결 지도에 필요한 새 기능은 **새 이름으로 추가만** 한다(삭제·시그니처 변경 금지). 원형 모티프 컴포넌트(FocusRing, GyeolRings, ContourRibbon)는 export는 남기되 앱이 쓰지 않게 하고, 대체물(예: ProgressLine)을 새로 추가한다. 추가한 API는 `team/dev-notes-fx.md` 맨 위 'API 변경 기록'에 적는다.
