## 1. 진단 — v1 '오늘' 벤토가 눈을 피로하게 한 이유

v1 목업의 오늘 화면(데스크톱)을 그대로 세어 봤다.

| 항목 | v1 오늘(1440) | 문제 |
|---|---|---|
| 동시에 보이는 상자(카드·패널) | 9개 (벤토 7 + 우측 패널 2) | 상자마다 테두리·제목·숫자가 있어 시선이 Z자로 9번 끊긴다. "대시보드"로 보이지 "작품"으로 보이지 않는다 |
| 큰 숫자 | 6개 (43분, D-6, 13, 54%, 25:00, 9겹) | 모두 크기가 비슷해 무엇이 지금 중요한지 화면이 말해 주지 않는다 |
| 인주(주 동작) 버튼 | 4개 (노트 열기, 집중, 집중 시작, 복습 시작) | v1 규칙 "주 버튼 1개, 인주 면적 5% 이하"를 v1이 스스로 어겼다 |
| 잔디 히트맵 | 182칸, 인주 5단계 | 화면에서 가장 시끄러운 고주파 무늬. 정보 가치에 비해 시각 무게가 가장 크다 |
| 중복 | '지금 수업'이 벤토와 우측 일정에 두 번, 타이머가 목표 카드와 우측 패널에 두 번 | 같은 사실을 두 번 읽게 함 |
| 크롬 비중 | 사이드바 248 + 우측 300 = 화면 너비의 38% | 내용보다 틀이 크다. iPad 가로(1180)에선 본문이 더 좁아진다 |
| 결 필드 | 앱 화면엔 없음 (히어로에만) | 사용자가 가장 좋아한 요소가 정작 앱에서는 사라지고, 앱은 정적인 상자 모음이 됐다 |
| 첫 시야 글자 줄 수 | 약 60줄 | 한 번에 읽을 수 있는 양(약 10줄)의 6배 |

**결론:** 기능을 다 보여 주려고 했지, 지금 무엇을 하면 되는지 말해 주지 않았다. 피로의 원인은 정보량 자체보다 **동등한 무게의 초점이 여러 개**라는 데 있다.

## 2. 화면 구성 원칙 v2 — "한 화면 한 초점"

| # | 원칙 | 규칙 (개발·리뷰에서 그대로 체크) |
|---|---|---|
| P1 | **초점 1개** | 모든 화면은 '초점 문장' 하나 + 주 동작 하나로 시작한다. 초점 문장은 Hahmlet 600, `--fs-display`. 숫자는 타일이 아니라 문장 안에 넣는다("43분 남았어요") |
| P2 | **조용한 주변부** | 초점 외 정보는 최대 3개, `--text-3`, 본문 크기 이하. 상자·테두리 없이 여백 위의 글자로만 둔다 |
| P3 | **노출 상한** | 아래 예산표를 넘으면 접거나 다음 단계로 미룬다 |
| P4 | **점진적 공개 4단계** | 0 초점(항상) → 1 주변부(항상, 흐림) → 2 펼치기(탭·호버·스크롤로 그 자리에서 열림, 한 번에 하나) → 3 꺼내기(⌘K, 전부 검색) |
| P5 | **타이포가 위계를 만든다** | 한 화면에 글자 크기 3종까지. 초점과 다음 크기의 비율 2.5배 이상. 색 대신 크기·굵기·여백으로 위계 |
| P6 | **결 필드 = 정보 매체** | 필드는 장식이 아니라 데이터를 그린다 (아래 표). 카드로 보여 주던 진도·집중·압박을 무늬로 옮긴다 |
| P7 | **크롬은 부를 때만** | 상시 내비는 떠 있는 독 하나. 패널은 필요할 때만 열리고, 필기 중에는 크롬이 3px 줄로 접힌다 |
| P8 | **움직임은 한 번에 하나** | 배경 필드를 빼면 동시에 움직이는 전경 요소는 1개. 연출이 끝나야 다음 연출 |

**화면당 노출 예산 (첫 시야 기준)**

| 항목 | 상한 | v1 오늘 | v2 오늘 |
|---|---|---|---|
| 초점 문장 | 1 | 0 | 1 |
| 인주 주 버튼 | 1 | 4 | 1 |
| 보조 동작(조용한 텍스트 버튼) | 2 | 5+ | 1 |
| 큰 숫자 | 1 | 6 | 1 (문장 안) |
| 작은 숫자 | 3 | 20+ | 3 |
| 상자(카드·테두리 있는 면) | 1 | 9 | 0 |
| 과목 색 점 | 3 | 20+ | 1~3 |
| 상시 내비 표면 | 1 | 2 | 1 (독) |
| 첫 시야 글자 줄 수 | 10 | 약 60 | 약 8 |

**결 필드가 표현하는 데이터 (P6)**

| 필드 속성 | 데이터 | 예 |
|---|---|---|
| 옹이 위치 | 지금 초점의 대상 | 초점 문장 옆 황금비 지점. 화면이 바뀌면 옹이가 미끄러져 이동 |
| 옹이 둘레 인주 고리 수 | 오늘 집중한 세트 수 (25분 = 1겹) | 2시간 10분 → 5겹. 세트가 끝나는 순간 한 겹이 새로 그려진다 |
| 흐름 속도 | 시간 압박 | 가장 가까운 시험이 D-3 이하면 1.6배, 평소 1.0, 밤 0.6 |
| 등고선 밀도 | 남은 할 일 양 | 복습 0장이면 성글고(간격 넓음), 40장이면 촘촘 |
| 색조 | 과목 렌즈 / 지금 수업 과목 | 일반물리 렌즈 → 옹이 주변이 하늘색으로 물듦(면적 5% 이하) |
| 물결 | 사용자의 손길 | 누른 자리에서 번짐 |

**왜 이게 수상작 수준인가**
1. **편집 디자인의 구도**: 거대한 한글 문장 + 넓은 여백 + 생성형 무늬. 잡지 표지처럼 한 장면이 완성된다(조사 3-1 FOLLOW.ART의 '도구 화면 자체가 작품').
2. **데이터 아트가 곧 UI**: 사람마다, 날마다 무늬가 다르다. 공부를 많이 한 날은 화면이 눈에 띄게 달라진다(W2 확장).
3. **끊기지 않는 장면 전환**: 화면이 바뀔 때 필드는 다시 그려지지 않고 같은 물결이 이어서 흐른다(조사 3-1 Igloo의 연속성).
4. **절제**: 먹·종이·인주 2+1색, 초점 1개. Lando Norris식 고대비 정체성을 과밀함 없이 유지.
5. **촉감**: 누르면 물결, 펜이 다가가면 옹이가 따라온다. 기능 없는 순간에도 만지는 재미가 있다.

## 4. 화면 스펙 (M0 범위)

### 4-1. 오늘 v2 — 상황에 따라 초점이 바뀐다

1분마다, 그리고 앱이 다시 보일 때(`visibilitychange`) 아래 표를 **위에서부터** 검사해 처음 맞는 상황을 초점으로 삼는다.

| 우선 | 상황 | 조건 | 초점 문장 (2줄) | 주 동작 / 조용한 동작 | 주변부 3 | 필드 분위기 |
|---|---|---|---|---|---|---|
| 1 | 첫 실행·빈 상태 | 시간표 0개 | 시간표부터 넣어 볼까요? / 수업만 넣으면 과목 공간이 저절로 생겨요. | 시간표 만들기 / 샘플로 둘러보기 | — | 성긴 등고선, 옹이 약하게 숨 쉼 |
| 2 | 수업 중 | 지금 시각이 수업 시간 안 | 일반물리 수업 중이에요. / 43분 남았어요. | 노트 열기 / 녹음하며 쓰기 | 다음 수업, 복습 n장, 가장 가까운 D-day | 과목색 옹이, 속도 0.8, 고리 = 수업 진행도(가장 안쪽 고리가 채워짐) |

## 6. 모션 컴포넌트 API 제안 (`src/fx/index.ts` 계약 초안)

전제: React 19 + `motion` 14(DOM 연출) + WebGL2 셰이더(필드). 필드는 **노이즈 값의 iso-line**으로 등고선을 그린다(`fract(v)`와 `fwidth(v)`로 1px 선, 4번째마다 굵은 계곡선). 물결·옹이·와이프는 유니폼이다.

| 이름 | 종류 | 역할 | 주요 props / 반환 |
|---|---|---|---|
| `FieldProvider` | 컴포넌트 | 앱 루트에 1번. 전체 화면 고정 캔버스 1개, 렌더 루프, 등급 판정, 정지 규칙 | `level: 'rich'\|'calm'\|'off'`, `theme: 'dark'\|'light'`, `tier?: 'auto'\|'A'\|'B'\|'C'`, `debug?: boolean`, `children` |
| `FieldMood` | 컴포넌트(렌더 없음) | 화면이 자기 분위기를 선언. 바뀌면 보간 | `preset: MoodName`, `override?: Partial<Mood>`, `knotRef?: RefObject<Element>`, `transitionMs?: number`(기본 900) |
| `useFieldKnot` | 훅 | 옹이를 DOM 요소 위치에 고정(스크롤·리사이즈 추적) | `(ref, { strength?, followPointer? })` |
| `useRipple` / `RippleSurface` | 훅 / 컴포넌트 | 물결 발생. Surface는 영역 안 `pointerdown`마다 자동 | `ripple(x, y, { strength?, accent? })` / `{ disabled?, strength?, as? }` |
| `useSeal` | 훅 | 완료 순간 인주 번짐(+선택: 도장) | `seal(at: Element\|{x,y}, { stamp?: { text, sub? } })` |
| `useFieldPause` | 훅 | 필기·입력 중 필드 정지·흐림 | `(active: boolean, reason: 'ink'\|'typing'\|'overlay')` |
| `useFieldNavigate` | 훅 | 라우터 이동 + 결 와이프 + View Transition 묶음 | `navigate(to, { origin?: Element\|{x,y}, direction?: 'forward'\|'back' }): Promise<void>` |
| `useFieldData` | 훅 | 데이터 → 필드(고리 수, 밀도, 속도) | `({ rings?: number, load?: 0..1, pressure?: 0..1, tint?: string })` |
| `RevealText` | 컴포넌트 | 초점 문장 줄 마스크 등장 | `lines: ReactNode[]`, `as?`, `stagger?`(90), `delay?`, `trigger?: 'mount'\|'inView'`, `swapKey?`(바뀌면 나감→들어옴) |
| `CountUp` | 컴포넌트 | 숫자 카운트업(세션당 1회) | `value`, `format?`, `duration?`(600), `once?` |
| `FocusRing` | 컴포넌트 | 원형 타이머 링 + 궤도 빛(v1 W3) | `progress: 0..1`, `size?`, `color?`, `state: 'idle'\|'running'\|'paused'\|'done'`, `drawIn?`, `children` |
| `Stamp` | 컴포넌트 | 인주 도장(v1 W5) | `show`, `text`, `sub?`, `onDone?` |
| `GyeolRings` | 컴포넌트 | 나이테(이번 주 결) SVG | `items: { size: number; color: string }[]`, `grow?` |
| `ContourRibbon` | 컴포넌트 | 오늘의 흐름 가로 등고선 띠(SVG) | `segments: { start; end; kind: 'class'\|'focus'; color }[]`, `now: Date` |
| `useMotionPrefs` | 훅 | 현재 모션 상태 | `{ level, reduced, tier, fps }` |
| `useIdle` | 훅 | 무입력 감지(숨 쉬는 대기) | `(ms) => boolean` |

```ts
// src/fx/index.ts — 타입 초안
export type MotionLevel = 'rich' | 'calm' | 'off';
export type Tier = 'A' | 'B' | 'C';
export type MoodName = 'landing' | 'today' | 'notes' | 'graph' | 'review' | 'planner' | 'focus' | 'settings';
export interface Mood {
  speed: number; step: number; aniso: [number, number];
  knot?: [number, number] | null; knots?: Array<[number, number]>; knotStrength: number;
  tint?: string; tintAmount?: number; rings?: number; breath?: boolean; dim?: number;
}
export declare const MOODS: Record<MoodName, Mood>;
// 셰이더 유니폼(모션 개발자 내부): uTime uSpeed uScale uAniso uStep uLineWidth uMajorEvery
// uKnot[4] uKnotStrength uKnotRadius uRipple[4](x,y,t0,amp) uPhase uTint uTintAmount
// uSeal uSealPos uRings uBreath uDim uColorMinor uColorMajor uAccent uResolution
```

연결 규칙(앱 개발자용): 루트에 `FieldProvider`, 각 라우트 화면 맨 위에 `<FieldMood preset="…"/>`, 독·⌘K 이동은 `useFieldNavigate`, 노트 편집기는 `useFieldPause(isEditing,'ink')`, 완료 이벤트는 `useSeal`. 컴포넌트는 `useMotionPrefs`를 읽어 '끔'이면 스스로 즉시 전환한다.

## 7. 프로토타입

`team/mockup/today-v2.html` (35KB, 한 파일, 외부 요청은 Google Fonts뿐): '오늘' v2만 담았다.
- 셸: 폰은 아래 독 6칸, iPad는 아래 독 7칸, 데스크톱(≥1200)은 왼쪽 떠 있는 레일. 상단 바는 공간 이름·렌즈·⌘K·테마만 있고, 아래로 스크롤하면 숨는다.
- 초점: 오른쪽 위 '시연 상황' 선택으로 4-1의 상황 8개를 바꿔 볼 수 있다. 문장 줄 마스크 교체, 결 와이프(등고선 위상 이동 + 물결), 옹이 이동, 속도·밀도·색 보간이 함께 일어난다.
- 필드 = 데이터: 옹이 둘레 인주 고리가 오늘 집중 세트 수(주 버튼을 누르면 한 겹이 늘어 완료 순간을 흉내 냄). 누르면 물결, 마우스·펜 호버에 옹이가 따라오고, 20초 무입력이면 숨 쉰다.
- 주변부 3개는 누르면 그 자리에서 선반이 열린다(Esc로 닫힘). 아래로 스크롤하면 '오늘의 흐름'(등고선 띠), '이번 주 결'(나이테 7개), '이어서 하기' 3개 장이 나온다.
- 필드는 v1 목업의 Canvas 2D 마칭 스퀘어 코드를 줄여 재사용했다. 실제 앱은 6장의 WebGL2 계약으로 만든다.
- 검증: 스크립트 구문 검사(node --check)는 통과했다. **브라우저 확인은 하지 못했다.** 이 세션의 미리보기 도구가 이전 작업 폴더의 실행 설정을 읽어서 새 폴더를 띄우지 못했다. 리더가 `.claude/launch.json`의 `gyeol-docs`로 `/mockup/today-v2.html`을 390·820·1180·1440 폭에서 한 번 열어 봐 주면 좋겠다.
