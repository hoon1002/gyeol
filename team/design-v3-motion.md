# 디자인 v3 모션: 기능 = 하늘의 사건

작성: 아트 디렉터 · 2026-10-17 · 상태: 개발 계약용 (모션 개발자 `src/fx/**`, 앱 개발자 `src/**`)
바탕: `team/v3-integration-brief.md`(사용자 원문·리더 결정·최적화 진단·API 계약 규칙), `team/design-v3.md`(§2 하늘, §5 안전, §6 데이터 별), `team/dev-notes-galaxy.md`(엔진), `team/dev-notes-app.md`(앱 구조)

> **한 줄:** 하늘은 장식이 아니라 앱의 피드백 채널이다. 사용자가 무언가를 하면 하늘에서 그 일에 맞는 **빛의 사건**이 하나 일어난다. 움직이는 것은 빛뿐이고 화면은 움직이지 않는다.

## ★ 카메라 반영 (2026-10-17, `team/design-v3-camera.md`가 우선)

공간 이동과 첫 진입은 이제 **은하 속 장소로의 비행**(900–1300ms)이다. 아래 행은 원래 행보다 이 칸이 우선한다. 나머지 사건(V1–V13)과 안전 상한은 그대로다.

## 0. 원칙과 v3에서 바뀐 수치

| # | 원칙 |
|---|---|
| M1 | **행동 하나에 사건 하나.** 모든 핵심 행동은 하늘에 고유한 사건을 하나 일으킨다(2장 지도). 사건이 곧 완료 피드백이므로 토스트·도장·감탄 문구는 쓰지 않는다 |
| M2 | **움직이는 것은 빛뿐.** 별의 밝기, 빛줄기의 머리, 별가루만 움직인다. 화면 전체 회전·확대·이동·패럴랙스·왜곡·동심원·맥동은 계속 0(design-v3 §5) |
| M3 | **UI와 하늘은 같은 박자.** 같은 프레임에 시작해 같은 이징으로 같은 시각에 끝난다(3장). 검은 화면·흰 번쩍임 0 |
| M4 | **하늘은 실패를 말하지 않는다.** 오류·삭제·포기는 조용히 꺼질 뿐이다. 붉은 경고 연출은 없다(오류는 UI 글자로만) |
| M5 | **소리·진동 없음.** 2장의 모든 행이 무음이다 |
| M6 | **사건이 굽기를 부르지 않는다.** 모든 사건은 매 프레임 그리는 동적 층(점·선 수십 개, 유니폼)에서만 그린다. 정적 하늘은 앱 시작 때 한 번만 굽는다(리더 진단) |

| 항목 | design-v3 | v3 모션 (이 문서가 우선) | 이유 |
|---|---|---|---|
| 공간 전환 시간 | 노출 900ms, 내용 160 + 280ms | **하늘·내용 모두 450ms, 한 타임라인** | "팟 팟" 지적. UI와 하늘을 한 박자로 맞춘다 |
| 공간별 노출 범위 | 30–100% | **50–100%, 한 번 전환에 바뀌는 폭 ≤ 45%p** | 어두워졌다 밝아지는 느낌을 줄인다 |
| 회절 스파이크 | 없음 | **별이 태어나는 순간에만** 4갈래 ≤ 11px, ≤ 1.2초 | 리더 예시. 방향은 고정, 회전 없음 |
| 유성 | 환경 유성만(3분에 1회) | 환경 유성 + **신호 유성**(큰 완료 때만, 20초에 1회 이하) | 완료 신호 |
| 별가루 | 수직 낙하만 | 집중 중에는 **탄생 자리로 아주 느리게 모임**(각도 ≤ 25°) | 집중의 몰입감 |

## 1. 빛의 움직임 어휘 (허용 목록, 이 밖의 움직임은 금지)

| 코드 | 이름 | 무엇이 | 시간 · 이징 | 상한 (속도 · 밝기 · 면적) |
|---|---|---|---|---|
| **V1** | 피어남 (별 탄생) | 한 점에서 빛이 피어난다. 중심 밝기가 0 → 100%로 오르고, 가우시안 할로가 0 → 14px로 커졌다가 9px로 가라앉는다. 4갈래 회절 스파이크는 팔 하나가 0 → 11px로 길어졌다가 4px로 짧아진다 | 1200ms. 오름 400ms `out`, 가라앉음 800ms `inout` | 별 하나당 영역 40×40px 이하. 할로 불투명도 35% 이하(고리 테두리 없이 가우시안만). 스파이크 불투명도 45% 이하, 방향 고정 |
| V1s | 작은 피어남 | V1에서 스파이크를 빼고 할로를 6px로 줄인 것 | 800ms `out` | 영역 16×16px 이하 |
| **V2** | 그어짐 (별자리 선) | 두 별 사이에 빛의 머리(지름 4px, 100%)가 지나가며 0.75px 선을 남긴다. 선은 28%로 가라앉는다 | 600ms(길이 120px 이하) ~ 900ms(260px). `std`. 남은 선은 300ms 동안 28%로 | 머리 속도 400px/s 이하. 선 길이 260px 이하(넘으면 즉시 표시). 동시에 1개, 대기열 간격 150ms |
| **V3** | 다시 켜짐 | 희미한 별이 제자리에서 목표 밝기로 밝아진다. 6px 할로가 잠깐(0 → 6 → 3px) 생긴다 | 800ms `out` | 위치 이동 0. 동시에 3개 이하 |
| V4 | 꺼져 감 | 별이 목표 밝기 또는 0으로 어두워진다 | 600ms `inout` | 번쩍임 없이 내려가기만 한다 |
| V5 | 유성 | 신호 유성: 화면 위쪽 40% 안에서 띠 방향(왼쪽 아래 ±20°)으로 80–140px 빛줄기 | 700ms(나타남 150 · 유지 250 · 꼬리 300) | 속도 200px/s 이하, 가장 밝을 때 75%, 폭 1px. 신호 유성은 20초에 1회 이하. 신호 유성이 지나간 뒤 60초 동안 환경 유성(3분에 1회)은 쉰다 |
| **V6** | 노출 미끄러짐 | 하늘 전체의 노출, 보이는 별의 한계, 위상 색조가 선형 빛(HDR) 공간에서 보간된다. 합성 셰이더의 유니폼만 바꾼다 | 450ms `std` (공간 전환). 시간대 위상은 60초 | 한 번에 바뀌는 폭 45%p 이하. 단조 변화(넘침·검게 꺼짐 없음). 위치 이동 0 |
| V7 | 별가루 모임 | 탄생 자리 반경 300px 안 별가루의 30%만 낙하 방향을 그 자리 쪽으로 튼다 | 방향 전환 4초 `inout`. 풀 때도 4초 | 속도 12px/s 이하 그대로, 수직에서 25° 이하로만 기운다. 동시 입자 수 변화 없음 |
| V8 | 손끝 별빛 | 누른 자리(또는 포인터·펜 근처) 별이 밝아진다(기존 useRipple의 대체) | 켜짐 250ms, 유지 0.6초, 꺼짐 900ms | 반경 120px(펜 80px), 최대 +35%, 위치 이동 0 |
| V9 | 다가옴 | 시험 별의 밝기와 H-α 성운이 날짜에 맞는 값으로 천천히 바뀐다 | 2000ms `inout` (하루 첫 보기 때 1회) | 성운 반경 48px 이하, 불투명도 18% 이하 |
| V10 | 물듦 | 과목 반사 성운의 색이 바뀌고, 고른 과목이 아닌 데이터 별은 25%로 낮아진다 | 600ms `inout` | 색 섞음 10% 이하, 성운 면적 화면의 8% 이하 |
| V11 | 반짝 (확인) | 가까운 별 하나가 잠깐 +40% 밝아졌다 돌아온다 | 300ms(오름 100 · 내림 200) | 같은 자리 5초에 1회 이하. 별 하나만 |
| V12 | 가라앉음 | 오버레이(⌘K·시트)가 열리면 하늘 노출을 ×0.6으로 낮추고 새 별가루를 멈춘다 | 열림 200ms `out`, 닫힘 260ms `out` | 밝기만 바뀐다 |
| V13 | 띠 부풂 | 은하 띠 전체 밝기 +8% | 2000ms(오름 600 · 유지 600 · 내림 800) | 하루에 같은 이유로 1회 |

**이징:** `std` = `cubic-bezier(.4,0,.2,1)`, `out` = `cubic-bezier(.22,1,.36,1)`, `inout` = `cubic-bezier(.65,0,.35,1)`. 스프링·오버슈트는 없다.

**공통 상한 (모든 어휘)**
- 동시에 진행하는 **큰 사건**(V1 · V2 · V5 · V13)은 1개, **작은 사건**(V1s · V3 · V4 · V11)은 3개까지. 넘치면 대기열에 150ms 간격으로 넣고, 대기 2초가 지난 사건은 최종 상태로 건너뛴다.
- 사건이 바꾸는 픽셀은 화면의 2% 이하. V6·V12·V13은 밝기만 바뀌므로 면적에서 뺀다.
- 같은 자리에서 연속으로 밝아지는 사건은 350ms 이상 띄운다(초당 3회 미만, WCAG 2.3.1).
- 위치가 움직이는 것은 V2의 빛 머리, V5 유성, 별가루뿐이다.
- 사건 하나의 JS 비용은 프레임당 0.2ms 이하. 정적 하늘 굽기는 0회.

**모드별 대체 규칙** (2장 표의 '절제' 칸이 비어 있으면 이 규칙을 따른다)

| 모드 | 규칙 |
|---|---|
| 풍부 (기본) | 표 그대로 |
| 절제 | V1 → V1s(스파이크 없음). V2 → 머리 없이 선이 300ms 페이드. V5 → 생략. V7 → 생략. V13 → +4%. 시간은 최대 600ms |
| 정지 · OS 동작 줄이기 | 모든 사건이 **최종 상태로 즉시** 바뀐다. 정지 장면을 1회 다시 그리되 크로스페이드는 없다. 별가루·유성·반짝임은 0 |

## 2. 연결 지도 (기능 → 하늘 사건)

'어디서'의 자리 이름은 design-v3 §2·§6을 따른다: 오늘의 자리, 탄생 자리(= 다음 오늘의 별 자리), 복습 자리(57° 사선), 시험 별 자리, 과목 성운 자리. **모든 행은 소리·진동이 없다.**

## 3. 화면 전환 안무 (공간 A → B, 한 타임라인 450ms)

**t = 0은 클릭(포인터 업) 프레임이다.** 하늘과 UI가 같은 프레임에 시작한다. 하늘의 노출은 선형 빛 공간에서 보간한 뒤 톤매핑하므로, 중간에 어두워지는 구간이 없다.

| t (ms) | 하늘 | UI | 메인 스레드 |
|---|---|---|---|
| 0 | V6 시작: 노출·별 한계·위상 색조 A → B (`std`, 450ms). 데이터 층 A 페이드아웃 시작(0 → 225, `std`). 별가루·반짝임은 그대로 흐른다 | A 내용 opacity 1 → 0 시작(180ms, `cubic-bezier(.4,0,1,1)`). 독 활성 점 A → B 크로스페이드 시작(200ms) | 라우트 commit. 이 프레임 작업 ≤ 8ms. 굽기·무거운 계산은 `requestIdleCallback`으로 미룬다 |
| 16–120 | 보간 중 | B 화면 마운트(opacity 0, 레이아웃만). 이 사이에 lazy 청크가 오면 마운트 | React 렌더 ≤ 8ms씩 나눠서 |
| 170 | — | B 들어옴 시작: 명사구 170 → 390 · 메타 200 → 420 · 동작 230 → 450 (각 220ms, `out`, opacity만) | — |
| 180 | — | A 완전히 사라짐 | — |
| 225 | 데이터 층 B 페이드인 시작(225 → 450) | — | — |
| 450 | V6 끝. B 하늘 고정 | 끝. 셸·내용 모두 B | 미뤄 둔 작업 시작 가능 |

- View Transitions API는 **내용 루트에만** 쓴다(`[data-gx-vt-root]`). 하늘 캔버스는 `view-transition-name: none`으로 스냅샷에서 빼고, 하늘은 자체 V6로 바꾼다. 상단 요소·독은 이름을 따로 붙여 전환 중에도 흐려지지 않게 한다.
- **B가 450ms 안에 준비되지 않으면** 하늘은 예정대로 450ms에 끝나고, 내용은 준비된 프레임부터 220ms 페이드인한다. 스켈레톤·스피너는 쓰지 않는다. 명사구가 먼저 준비되면 명사구만 먼저 들어온다.
- **전환 중에 또 누르면(B → C):** 처음부터 다시 하지 않고 **이어 받는다.**
  1. 하늘: 지금 값에서 C 값으로 새 450ms 보간을 시작한다. 이때 **지금 속도를 이어 받는다**(Hermite 보간이나 임계 감쇠, 속도 불연속 0).
  2. UI: 부분적으로 들어온 B는 지금 opacity에서 0으로(남은 비율 × 180ms) 내보내고, C는 그 클릭 기준 +170ms부터 들어온다.
  3. 데이터 층: B를 지금 값에서 0으로 내리고, C는 +225ms부터 올린다.
  4. 대기열은 없다. 마지막으로 누른 곳이 이긴다.
- 같은 공간을 다시 누르면 하늘 사건 없이 맨 위로 스크롤만 한다(스크롤 300ms, 동작 줄이기면 즉시).
- 큰 사건(V1·V2·V5)이 진행 중일 때 공간을 이동하면, 사건은 데이터 층과 함께 사라진다(225ms). 그 사건의 최종 상태는 데이터에 이미 반영되어 있으므로 B나 다음 방문에서 최종 상태로 보인다.

## 4. 첫 화면 진입 안무 (앱을 열 때, 세션당 1회)

목표는 **눈이 어둠에 익는 경험**이다. 밤하늘을 보면 처음에는 밝은 별만 보이다가 곧 희미한 별과 은하수가 드러난다. 그 과정을 1.1~1.8초로 줄인다.

| t (ms) | 하늘 | UI |
|---|---|---|
| 0 | 첫 페인트. `html` 배경은 `--sky-1`(흰 번쩍임 0). WebGL이 아직이면 같은 색의 CSS 그라디언트를 깔아 두고, 준비되는 순간 200ms 크로스페이드. 노출 55%, 0~1등급 별만 | 아무것도 없음 |
| 0 → 900 | 노출 55 → 100% (`out`). 2등급은 200 → 800에, 3등급과 분해 안 된 별빛은 400 → 1100에 켜진다(늦게 켜지는 희미한 별) | — |
| 400 | — | 명사구 opacity 0 → 1 (320ms) |
| 460 / 520 | — | 메타 / 동작 (각 320ms) |
| 600 | — | 상단 요소·독 (240ms) |
| 700 → 1500 | **오늘의 별이 태어난 순서대로 하나씩 V3**(0 → 100%, 각 400ms). 간격 = min(160ms, 800 ÷ 별 수). 두 번째 별부터는 켜질 때 앞 별과의 선이 V2로 그어진다(이 안무에서는 200ms로 빠르게) | — |
| 900 → 1500 | 시험 별 0 → 오늘 값(V9를 600ms로) | — |
| 1500 → 3500 | 별가루가 0개에서 정해진 수까지 늘어난다(생성률 램프 2초). 환경 유성은 최소 30초 뒤부터 | — |

- 끝: 별이 0개면 1.1초, 10개면 약 1.8초. **어느 순간에 눌러도** 200ms 안에 최종 상태로 건너뛰고, 입력은 막지 않는다.
- 횟수: `sessionStorage`에 플래그를 두고(try/catch, 실패하면 매번 짧은 판) 세션당 1회. 숨겼다가 30분 넘게 지나 다시 보이면 2-1의 2번(400ms)만 한다.
- 절제: 노출만 600ms, 별자리는 바로 최종. 정지: 최종 장면을 첫 페인트에 바로.
- 성능: 정적 하늘 굽기와 셰이더 워밍업은 이 1.1초 안에 끝낸다. 굽기가 늦으면 0~1등급 별과 노출만으로 진행하고, 구운 하늘은 준비된 프레임부터 300ms 크로스페이드로 올린다. 굽기는 진입 뒤에 다시 일어나지 않는다.

**연결 예 (앱 개발자)**
```tsx
// 집중
const sky = useSkyEvent()
useEffect(() => { sky.gatherDust(running ? 'next' : null) }, [running])
useEffect(() => { if (running) sky.growStar(sessionId, progress) }, [secondTick])
onComplete(() => { sky.birthStar({ id: sessionId, at: 'next', kind: 'set', subject }); if (prevId) sky.drawLink(prevId, sessionId, { layer: 'today' }) })
// 복습 평가
const level = { again: 0.25, hard: 0.85, good: 0.95, easy: 1 }[rating]
rating === 'again' ? sky.fadeStar(card.id, { to: 0.25, ms: 300 }) : sky.relight(card.id, level, { glint: rating === 'easy' })
// 링크
onLinkCreated((a, b) => sky.drawLink(a, b, { layer: 'graph' }))   // 편집 중이면 보류함에 쌓였다가 재생
```

- 모든 함수는 **멱등이고 실패하지 않는다.** 같은 id로 두 번 부르면 두 번째는 최종 상태 맞추기만 한다. WebGL이 없으면 아무 일도 하지 않는다.
- 사건은 데이터의 결과다. 새로고침하거나 공간을 이동하면 `useSkyStars`가 최종 상태를 맞추므로 사건을 다시 재생하지 않는다.
- 추가한 이름은 모션 개발자가 `team/dev-notes-fx.md` 맨 위 'API 변경 기록'에 적는다.
